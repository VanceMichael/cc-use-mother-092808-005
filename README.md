# 央企新兴产业价值贡献归集

核算央企战略性新兴产业、研发和公共服务的价值贡献。本仓库在领域资料
（`contracts/`、`fixtures/`、`src/news_context_005.py`）之外，交付了一套
可直接运行的**价值贡献治理后端** `src/value_governance/`：统一维护组织
边界、产业分类、项目任务、投资批次、研发费用、基础研究属性、成果转化、
公共服务贡献与内部交易抵销，并对报告期关账、特殊归类审批、批量导入和
历史更正实施可审计的治理规则。

## 治理规则（对应 2030 年规划场景）

1. **一个联合项目只能有一份贡献账。** 产业板块、研究院、公共服务单位
   就同一项目/任务/批次报送的金额先汇总为毛额，再按经集团数据办公室
   登记、份额合计恰为 1 的分摊规则分配到单位；规则版本化、只新增不
   覆盖。多单位申报却没有规则，或申报构成与批准份额偏差超过 1 个
   百分点，关账一律阻断。
2. **营业收入能对上，靠的是抵销后净口径。** 集团内部交易必须经买方
   双边确认（MATCHED）才进入抵销，按项目战新属性分别冲减增加值与
   收入；待确认（PENDING）与争议（DISPUTED，只能由复核人员裁决）
   的交易阻断关账。
3. **战新增加值与基础研究投入以审批为准。** 项目产业目录重分类、
   逐笔战新产出认定、基础研究属性认定都走"业务单位提交证据、财务
   复核人员批准"流程；**提交人不得批准自己的申请**，仅申请未批准
   的属性不计入指标且阻断关账。
4. **关账即冻结。** 关账成功时，公式版本（`FORMULA_VERSION`）、组织
   范围、产业目录、目标、分摊规则与全部贡献记录连同计算结果整体写入
   快照；此后目标、报送、主数据、投资批次均不可修改。规划人员改目标
   只能影响开放期间，历史期间继续读旧快照。
5. **历史错误走更正版本。** 已关账期间只能提交更正版本，双人
   （提交者与批准者不同）、只允许改金额/证据等业务列，公式、组织
   范围、报送单位、报告期、审批留痕冻结；批准后用**同一公式版本**
   重算并生成新快照修订（revision 递增，原快照保留），更正后仍存在
   未决阻断的不得应用。
6. **重组与拆分按权重平移。** 重组事件须声明每个源单位转出权重
   合计为 1，贡献按权重平移到目标单位、集团总额分文不差；项目
   拆分后父项目停止接报，贡献按子项目归集。
7. **批量导入识别重送、冲突交复核。** 批次按（报告期、客户批次号、
   内容指纹）识别：完全重送幂等忽略；同批次号不同内容直接拒收；
   同业务凭证不同内容挂起为冲突行，不落库、进复核队列，由复核人员
   裁决；关账期间冲突材料不得直接落库，只能走更正版本。
8. **未完成的关账与催补不因重启消失。** 关账是落库的多阶段作业，
   证据缺口转成持久化催补；进程重启后 `resume_jobs()` 续跑，缺口
   补齐则完成关账并核销催补，缺口仍在则保持阻断且不重复堆积。
9. **管理层看到的是真实差额。** 报告同时给出占比及同比变化、项目
   明细（各方毛额申报、批准份额与份额后归属）、费用归属、抵销过程
   （卖方/买方/确认人）、审批责任（提交人/复核人/证据号）与距规划
   目标的差额；战新增加值占比、基础研究投入占比、研发经费增速均以
   抵销后净额口径计算。

## 角色

| 角色 | 权限 |
| --- | --- |
| 集团数据办公室 DATA_OFFICE | 组织/产业/项目主数据、分摊规则、重组拆分、发起关账与更正 |
| 规划管理人员 PLANNER | 仅在开放期间维护规划目标 |
| 财务复核人员 REVIEWER | 批准特殊归类、裁决导入冲突与交易争议、批准更正版本 |
| 业务单位 UNIT_USER | 只能就本单位牵头或已列入分摊规则的项目报送与举证，无权批准 |

## 模块结构

```
src/value_governance/
  db.py       SQLite 建表与连接（金额定点字符串、外键、审计留痕）
  engine.py   纯函数计算引擎：分摊、重组、抵销、占比、目标差额、阻断项
  service.py  应用服务：RBAC、工作流、导入去重、关账快照、更正版本
  jobs.py     重启恢复：resume_jobs / sweep_reminders
  errors.py   治理错误类型
tests/
  vg_world.py                 最小集团场景夹具
  test_value_governance.py    28 个规则测试
```

## 快速示例

```python
from src.value_governance import GovernanceService

svc = GovernanceService("gov.db")
# …建立组织、产业、项目、报告期、用户（角色见上表）…
svc.define_allocation("office", "2030", "P1", "CONTRACT",
                      {"SE1": "0.5", "RI1": "0.3", "PS1": "0.2"})
svc.report_output("u_se", "2030", "P1", revenue="1000", value_added="500")
# …其余两方申报、内部交易确认、基础研究证据经复核批准…
svc.execute_close_job(svc.start_close("office", "2030"))
report = svc.management_report("2030")   # 关账后读冻结快照
```

进程重启后：

```python
from src.value_governance import GovernanceService, resume_jobs
resume_jobs(GovernanceService("gov.db"))  # 未完成的关账自动续跑
```

## 开发命令

运行测试：

```bash
python3 -m unittest discover -s tests -v
```

编译检查：

```bash
python3 -m compileall -q src
```

两条命令只读取仓库内文件，不需要连接外部业务系统。`*.db` 已被
`.gitignore` 忽略。

## 领域资料

`contracts/context.schema.json` 描述资料结构，`fixtures/context.json`
提供不含真实身份信息的示例，`src/news_context_005.py` 负责读取和校验
这些资料；`docs/domain-rules.md` 给出约束的完整展开。
